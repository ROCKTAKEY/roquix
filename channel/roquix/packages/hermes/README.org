* Hermes packages

=hermes= provides the CLI, local gateway, terminal UI, and web dashboard.
=hermes-desktop= launches that CLI as its local backend and propagates it
into the user's profile.  =hermes-desktop-light= connects to remote gateways
and has no local agent dependency.  All three use the same upstream release.

#+begin_src sh
guix install hermes
guix install hermes-desktop
guix install hermes-desktop-light
#+end_src

Launch the graphical variants with =hermes-desktop= or
=hermes-desktop-light=.  CLI and Desktop use the upstream =HERMES_HOME=
setting (normally =~/.hermes=) for user data.  Package updates belong to
Guix; the installed source and runtime live in the immutable store.

The supported target is =x86_64-linux=.  Electron is the only dependency
repackaged from a native binary release.  Python, the Python extensions, native
JavaScript build tools, and Node PTY bindings are built from source.  Existing
Guix packages are reused when their versions match the application lock.
Python 3.14 inherits Guix's CPython build definition because this Hermes release
supports 3.14 for normal execution; its older Python compatibility is limited
to updating an existing installation.

* Build contracts

Package assembly lives in =(roquix build hermes)=: source placement,
installation metadata, dependency links, and insertion of source-built WASM.
The CLI launcher bridge calls Hermes's own Python entry-point generator so its
launcher contract stays aligned with the upstream application.

The npm acquisition derivation runs with network access and verifies the
upstream lock.  It removes native binaries and precompiled WASM from the
acquired tree.  Offline builders supply source-built esbuild, Rolldown,
Tailwind, and Lightning CSS.  Shared native dependencies and their Cargo
package constructor live in =(roquix packages node-xyz)= so applications
can reuse them without importing one another's package definitions.  Yoga and es-module-lexer compile their WASM
from C/C++ with =emscripten-4= from =(roquix packages wasm)=.
Yoga uses =emcmake= for configuration and =emmake cmake --build= for
compilation so both steps inherit the toolchain wrappers' isolated include paths.  Vite hashing uses equivalent
JavaScript implementations.  Shiki uses its JavaScript regex engine throughout
the desktop and web UI.  Application compilation runs in ordinary
offline Guix builders.  Node PTY bindings use the headers of the packaged Electron
version.  CLI checks start the installed gateway in a disposable home and
verify its health endpoint without contacting a model provider.

Upstream's Light stamp identifies the product but does not itself exclude
the source-install bootstrap paths.  =light-remote-only.patch= makes its
resolver, installer IPC, and onboarding enforce the remote-only contract.
The native GUI test checks this contract as well as the regular Desktop's
connection to the packaged gateway.

#+begin_src sh
python3 tests/hermes-source-inputs.py
guix repl -L channel -- tests/hermes-build.scm
guix repl -L channel -- tests/hermes-package.scm
guix build -L channel hermes hermes-desktop hermes-desktop-light
guix shell node xorg-server dbus font-dejavu -- node tests/hermes-desktop.mjs \
  /gnu/store/…-hermes-desktop/bin/hermes-desktop
guix shell node xorg-server dbus font-dejavu -- node tests/hermes-desktop.mjs \
  /gnu/store/…-hermes-desktop-light/bin/hermes-desktop-light light
#+end_src

* Updating Python source inputs

Export core requirements from the upstream source with =uv export --frozen
--no-dev --no-emit-project --format requirements-txt -o requirements.txt=.
Use an empty source directory to fetch the source distributions selected for
CPython 3.14 on x86_64 Linux, verify them against =uv.lock=, and regenerate the
source-input module:

#+begin_src sh
guix shell python python-packaging -- \
  python3 scripts/update-hermes-python-inputs.py \
  /path/to/hermes/uv.lock /path/to/empty-source-directory VERSION \
  channel/roquix/packages/hermes-python-inputs.scm \
  --requirements /path/to/requirements.txt
#+end_src

The generator rejects source archives whose hashes differ from the lock.
For each Rust extension, import its =Cargo.lock= into the shared
=rust-crates.scm= using the group name recorded in =hermes-python-inputs.scm=.
Preserve unrelated Cargo input groups when regenerating that shared module.

Update the application source and Electron/header pins in =hermes.scm=,
Python source in =hermes-python.scm=, and native Node tools in
=hermes-node.scm=, =node-xyz.scm=, and =hermes-wasm.scm= together.  The npm source-cache hash includes binary removal
and Shiki configuration.  Verify the installed CLI and both GUI variants,
and run a temporary =guix pull= to check the channel-owned helper paths.
