* Roquix: Guix channel for me
Note that this channel depends on [[https://gitlab.com/nonguix/nonguix][nonguix]],
and it might include non-free software.

* How to Use?
Write to =.config/guix/channels.scm=:
#+BEGIN_SRC scheme -n
  (cons* (channel
          (name 'roquix)
          (url "https://github.com/ROCKTAKEY/roquix"))
         %default-channels)
         #+END_SRC

Run =guix pull= and use the resulting =guix=.  Roquix's channel metadata makes
the extension discoverable as =guix extra-profile=; a channel installation
does not require =GUIX_EXTENSIONS_PATH= or =GUILE_LOAD_PATH=.

* Bun and OpenCode
After adding this channel and running =guix pull=, install Bun or OpenCode with:

#+BEGIN_SRC sh
guix install bun
guix install opencode
#+END_SRC

These packages support =x86_64-linux=.

** Importing dependencies
=guix import-bun= generates Guix dependency definitions from =bun.lock= or
=bun.lockb=. Run it using the Guix profile produced by =guix pull= with this
channel. Importing requires network access to download dependency sources and
compute their hashes.

For a text lockfile, provide a source tree containing =bun.lock= and the
project's =package.json=. The generated Scheme expression is written to
standard output:

#+BEGIN_SRC sh
guix import-bun /path/to/project/bun.lock
#+END_SRC

The definition name is derived from the project name and version as
=%NAME-VERSION-npm-inputs=. If the root manifest has no version and exactly
one workspace has the same package name, that workspace supplies the version.

Use =--insert= to add or update definitions in an existing module. The target
file must already exist. Definitions with the same name are replaced:

#+BEGIN_SRC sh
guix import-bun --insert=channel/roquix/packages/bun-lock-inputs.scm \
  /path/to/project/bun.lock
#+END_SRC

Use =--project= when dependencies belong under a monorepo subdirectory:

#+BEGIN_SRC sh
guix import-bun /path/to/project/bun.lock --project=packages/example
#+END_SRC

This prefixes dependency installation paths with =packages/example= and adds
=example= to the generated definition name.

For a binary lockfile, specify the project source root with =--source=.
Conversion requires the roquix Bun package; Guix builds it if no substitute
is available:

#+BEGIN_SRC sh
guix import-bun /path/to/project/bun.lockb --source=/path/to/project
#+END_SRC

For a subproject's binary lockfile, specify both the source root and the
installation prefix:

#+BEGIN_SRC sh
guix import-bun /path/to/project/packages/example/bun.lockb \
  --source=/path/to/project --project=packages/example
#+END_SRC

Run =guix import-bun --help= to list the available options.

** Packaging Bun projects
Use =bun-build-system= from =(roquix build-system bun)= in Guix package
definitions. It runs =bun run build= and =bun test= by default. Specify the
files to install with =#:install-plan=.

Import the following modules in your package definition:

#+BEGIN_SRC scheme
(use-modules (guix packages)
             (guix gexp)
             (roquix build-system bun))
#+END_SRC

The following package fields install the contents of =dist/= at the root
of the package output:

#+BEGIN_SRC scheme
(build-system bun-build-system)
(arguments
 (list #:install-plan #~'(("dist/" "./"))))
#+END_SRC

| Argument          | Default             | Purpose                                                    |
|-------------------+---------------------+------------------------------------------------------------|
| =#:bun=           | roquix's =bun=      | Bun package to use                                         |
| =#:build-command= | =("run" "build")=   | Arguments passed to Bun; =#f= skips the command              |
| =#:test-command=  | =("test")=          | Test arguments passed to Bun; =#f= skips the command         |
| =#:node-modules=  | =#f=                | Dependency tree to use during the build                     |
| =#:install-plan=  | =#f=                | Required for the standard install phase; copy-build-system format |

Commands can be customized using gexps:

#+BEGIN_SRC scheme
(arguments
 (list #:build-command #~'("run" "build:release")
       #:test-command #~'("test" "test/unit")
       #:install-plan #~'(("dist/" "./"))))
#+END_SRC

The build environment cannot download dependencies, so first use
=guix import-bun= to generate their source definitions. In the following
example, =source= is the application's source and =%example-npm-inputs= is
the generated dependency list:

#+BEGIN_SRC scheme
(define modules
  (bun-node-modules
   source
   %example-npm-inputs
   #:name "example-node-modules"))
#+END_SRC

Add =#:node-modules modules= to the package's =arguments=. Dependencies are
available in the build directory; =#:install-plan= determines which files
are installed in the package output.

=bun-node-modules= freezes the lockfile and disables dependency lifecycle
scripts by default. Use =#:install-flags= to select workspaces:

#+BEGIN_SRC scheme
(bun-node-modules
 source
 %example-npm-inputs
 #:install-flags '("--filter" "./packages/example"))
#+END_SRC

For projects where =bun install= requests additional registry metadata,
create the dependency tree directly from the lockfile's installation paths:

#+BEGIN_SRC scheme
(bun-node-modules-from-layout
 %example-npm-inputs
 #:name "example-node-modules")
#+END_SRC

Workspaces in the source tree are linked according to =bun.lock=.

* lllmmm Home service
The =(roquix home services lllmmm)= module runs lllmmm as a user Shepherd
service and installs it in the Home profile:

#+BEGIN_SRC scheme
(use-modules (gnu home)
             (gnu services)
             (roquix home services lllmmm))

(home-environment
 (services (list (service home-lllmmm-service-type))))
#+END_SRC

Before activating the service, prepare =lllmmm/lllmmm.toml= under
=$XDG_CONFIG_HOME=, or =~/.config= when that variable is unset, empty, or
relative.  The file must configure at least one model with an existing model
file.  Backend executables such as =llama-server= must be available on the
service's =PATH= or named by absolute path in the TOML configuration.
Backend-specific environment variables can be set in =models.env=.

Use =home-lllmmm-configuration= to select another =lllmmm= package, an
absolute =config-file= path, or an absolute =log-file= path.  The log defaults
to =lllmmm.log= in Shepherd's user log directory.  For example:

#+BEGIN_SRC scheme
(service home-lllmmm-service-type
         (home-lllmmm-configuration
          (config-file "/home/alice/config/lllmmm.toml")))
#+END_SRC

=config-file= also accepts a Guix file-like object such as =plain-file= or
=local-file=.  Relative paths in TOML resolve against the configuration
file's directory.  A configuration stored in =/gnu/store= therefore needs
an absolute writable =state_dir= and absolute model paths.

The =stop-timeout= field defaults to 30 seconds.  It must exceed the TOML
=shutdown_timeout_secs= plus the server's five-second HTTP drain margin, so
lllmmm can reap its backend processes before Shepherd sends =SIGKILL=.

The service starts automatically.  Use =herd status lllmmm=,
=herd stop lllmmm=, and =herd start lllmmm= to manage it.

* Named extra profiles
=guix extra-profile= manages named profiles from declarative manifests and
combines already-built profile generations with =guix shell=.  It deliberately
does not re-evaluate a definition manifest while starting a shell.

** Definitions and generated profiles
A definition named =codex= is stored at:

#+BEGIN_EXAMPLE
$XDG_CONFIG_HOME/guix/extra-profiles/codex/manifest.scm
#+END_EXAMPLE

When =XDG_CONFIG_HOME= is unset, the path is
=~/.config/guix/extra-profiles/codex/manifest.scm=.  Its generated profile is:

#+BEGIN_EXAMPLE
~/.guix-extra-profiles/codex/codex
#+END_EXAMPLE

Names must match =[A-Za-z0-9][A-Za-z0-9._+-]*=.  Create or update the profile
explicitly:

#+BEGIN_SRC sh
guix extra-profile reconfigure codex
#+END_SRC

=reconfigure= accepts multiple names, =--all=, =--dry-run=, and the standard
Guix build options.  =--all= selects definitions only; a migrated generated
profile without a definition is not reconfigured.

** Shell composition
Start an interactive shell containing only the current =codex= generation:

#+BEGIN_SRC sh
guix extra-profile shell codex
#+END_SRC

The first =--= separates extra-profile names from arguments passed verbatim to
=guix shell=.  Project manifests must be explicit because the internally added
manifest disables =guix shell='s manifest auto-detection:

#+BEGIN_SRC sh
guix extra-profile shell codex -- \
  -CWNF \
  -m ./manifest.scm
#+END_SRC

Place optional =shell.scm= beside a profile's =manifest.scm= to configure
its shell.  The file is evaluated as Guile code, and its final expression must
return a =shell-configuration=.  Boolean fields default to =#f= and list fields
default to empty lists:

#+BEGIN_SRC scheme
(use-modules (roquix extra-profiles shell-configuration))

(let ((home (getenv "HOME")))
  (shell-configuration
   (container? #t)
   (network? #t)
   (pure? #t)
   (preserve '("^TERM$" "^DISPLAY$"))
   (environment-variables '(("EDITOR" . "emacs")))
   (extra-options '("--check"))
   (mounts
    (list
     (share (string-append home "/work")
            #:target "/workspace")
     (share (string-append home "/.cache/codex")
            #:target "/cache/codex"
            #:on-missing 'create-directory)
     (expose (string-append home "/.config/codex")
             #:target "/config/codex"
             #:on-missing 'skip)))))
#+END_SRC

The basic fields are =container?=, =network?=, =nesting?=, =link-profile?=,
=writable-root?=, =emulate-fhs?=, and =pure?=.  They accept =#t= or =#f=.
All except =container?= and =pure?= require an enabled =container?=.
=preserve= contains regular expressions naming environment variables to inherit;
they must be valid Guix regexps without an equals sign.  =environment-variables=
is an association list of string pairs =(name . value)=; values may contain
spaces and equals signs.  Names must be nonempty and cannot contain an equals
sign.  All option and environment strings must be NUL-free.

The expression runs when =extra-profile shell= starts, before Guix creates the
container.  Each =extra-options= string remains one command-line argument,
including spaces.  Specify mounts using =mounts=; =extra-options= cannot contain =--share=,
=--expose=, or the command boundary =--=.

=share= mounts a host path read-write; =expose= mounts it read-only.  Both accept
a host source path, optional =#:target=, and optional =#:on-missing=.  Source and
target paths must be absolute.  The target defaults to the source and is
normalized so that trailing slashes and =.= or =..= components do not hide
target conflicts.  Sources retain their spelling to preserve symbolic-link
resolution; they cannot contain an equals sign because Guix uses it to separate
source from target.  Directories, files, and sockets can be mounted.

The missing-source policy defaults to ='error=, which stops shell startup and
reports the profile name and source path.  ='skip= omits an absent source.
='create-directory= creates the source and missing parents with mode =0700=;
existing directory permissions are preserved, and an existing non-directory is
an error.  Creation is available for both =share= and =expose=, and occurs on
the host.  Permission errors, broken symbolic links, and non-directory parents
are errors even with ='skip=.  Missing target mount points inside the container
are created by Guix.

For multiple profiles, a boolean setting is enabled when any selected profile
enables it; =#f= contributes no request.  Environment inheritance patterns,
variable assignments, additional options, and mounts are collected in profile
order.  Later assignments to the same environment variable take precedence.
Basic flags are emitted once, followed by inheritance patterns, assignments,
additional options, and prepared mount arguments.  Container requirements and
mount conflicts are checked before directories are created.  Identical requests
for the same target are combined.  Different sources, access modes, or missing-source policies for
the same target are errors.  Parent mounts precede their children; independent
requests retain their order except where a parent must be moved before a child.

Mount requests require =(container? #t)= in at least one selected profile.
Additional options and explicit Guix arguments are passed through without
being interpreted as configuration fields, so supplying =-C= there does not
satisfy this requirement.  Saved settings and prepared mount arguments precede explicit arguments after the first =--=.  Keep the
command and its arguments after a second =--=.  Explicit Guix arguments are
passed through; the structured mount policies and conflict checks apply to
saved =mounts= settings.  Guix can still fail at execution if a source changes
after it has been checked.

Changes to =shell.scm= take effect on the next invocation without reconfiguring
the profile.  A name can have =shell.scm= without =manifest.scm= or a built
profile.  It appears in =extra-profile list=, has status =shell-only= in
=extra-profile show=, and starts a =guix shell= with an empty manifest.
=reconfigure --all= selects only names with =manifest.scm=.

Use a second =--= before a command executed inside the environment:

#+BEGIN_SRC sh
guix extra-profile shell codex -- \
  -CWNF \
  -m ./manifest.scm \
  -- codex
#+END_SRC

Multiple extra profiles are accepted.  Earlier names win file collisions;
an explicitly supplied project manifest wins collisions with extra profiles:

#+BEGIN_SRC sh
guix extra-profile shell codex texlive -- \
  -m ./manifest.scm \
  -- sh -c 'command -v codex'
#+END_SRC

=-p= and =--profile= are intentionally passed to =guix shell=, which rejects
their combination with the internally supplied manifest using its standard
diagnostic.  Options after the second =--= are command arguments and remain
unchanged.

At launch, each profile symlink is resolved through its current generation to
an immutable store directory.  The combined manifest is cached under
=$XDG_CACHE_HOME/guix/extra-profile/shell-manifests=, or under
=~/.cache/guix/extra-profile/shell-manifests= when =XDG_CACHE_HOME= is unset.
The cache directory has mode =0700= and manifest files have mode =0600=.

** Inspection and generation commands
#+BEGIN_SRC sh
guix extra-profile list
guix extra-profile show codex
guix extra-profile path codex
guix extra-profile generations codex
guix extra-profile generations codex 2d
guix extra-profile roll-back codex
#+END_SRC

=list= and =show= inspect filesystem state only.  They do not evaluate
definition manifests or start builds.  =roll-back= changes the mutable profile
symlink; the next shell launch consequently receives a different cache key.

** Guix Home
Guix Home can own definition files and XDG locations without performing an
implicit update.  For example:

#+BEGIN_SRC scheme
(use-modules (gnu services)
             (gnu home services)
             (gnu home services xdg)
             (guix gexp))

(services
 (list
  (simple-service
   'extra-profile-xdg-directories
   home-xdg-base-directories-service-type
   (home-xdg-base-directories-configuration
    (config-home "$HOME/.config")
    (cache-home "$HOME/.cache")))
  (simple-service
   'extra-profile-definitions
   home-files-service-type
   `((".config/guix/extra-profiles/codex/manifest.scm"
      ,(local-file "./codex-manifest.scm"))
     (".config/guix/extra-profiles/codex/shell.scm"
      ,(local-file "./codex-shell.scm"))))))
#+END_SRC

The XDG service exports the base-directory environment variables honored by
=guix extra-profile=.  Do not attach =guix extra-profile reconfigure --all= to
Home activation: a =guix home reconfigure= changes definitions, while the
separate extra-profile command intentionally decides when packages advance.

** Migration
An existing profile already located at
=~/.guix-extra-profiles/NAME/NAME= is immediately usable by =shell= even when
its definition is absent.  This supports temporarily unavailable definition
repositories and preserves the package derivations recorded in the current
generation.

To make a profile declarative, add its definition at the conventional path and
run =guix extra-profile reconfigure NAME=.  Profiles stored elsewhere should
be recreated at the conventional path from a manifest; avoid replacing them
with a link to another mutable profile because generation listing and rollback
are defined relative to the conventional profile basename.

** Developing and testing
Run the isolated unit and integration suite against the working tree with:

#+BEGIN_SRC sh
tests/extra-profile/run-tests.sh
#+END_SRC

The CLI tests use temporary Guix profiles that discover the checkout as a
channel.  This selects the working-tree modules even when roquix is installed:
Guix's channel module paths precede =GUILE_LOAD_PATH=.  The channel integration
test also runs without module-path or extension-path environment overrides.
Temporary HOME, XDG directories, and generated profile paths keep test state
separate from the user's Guix profile and extra profiles.

* Container launcher build system
=container-launcher-build-system= installs a wrapper in =bin/= that starts its
payload inside =guix shell -C=.  =#:payload= is a Guix package providing
=bin/<executable>=; the wrapper package has no source of its own.  Its
=inputs= are added to the container profile alongside the payload.

** Try and install the example
From this checkout, run the executable [[file:examples/hello-container.scm][GNU Hello example]] without installing it:

#+BEGIN_SRC sh
guix shell -L channel -f examples/hello-container.scm -- hello
#+END_SRC

Install the wrapper into the default Guix profile for ordinary =hello=
invocations:

#+BEGIN_SRC sh
guix package -L channel -f examples/hello-container.scm
hello
#+END_SRC

For an application defined as a named channel package, install it with
=guix install PACKAGE= after =guix pull=.  The installed executable starts the
container itself; callers do not need to supply =-C=.

** Runtime access
The wrapper uses a pure container and can preserve selected host environment
variables.  Add options to the package's =arguments= as needed:

#+BEGIN_SRC scheme
(arguments
 (list #:payload application-package
       #:executable "application"
       #:preserve-environment '("DISPLAY" "WAYLAND_DISPLAY" "XDG_RUNTIME_DIR")
       #:set-environment '(("APP_MODE" . "compact"))
       #:share '((environment "XDG_RUNTIME_DIR")
                 ("/home/user/work" . "/work"))
       #:expose '(("/home/user/assets" . "/assets"))
       #:network? #t))
#+END_SRC

=#:desktop-application= enables a private persistent home and a dedicated
nested Weston compositor for the named application.  Add =dbus= to its runtime inputs
for the private session bus.  The application ID is parsed before lowering,
and its display endpoint and state directory are checked before launch.
=#:desktop-temporary-directory= selects an existing disk-backed base directory
on the runtime host (default ="/var/tmp"=).  Desktop launches create an owned
=0700= directory under =BASE/roquix-tmp-UID/BOOT-ID/run-XXXXXX= and mount it
read-write at =/tmp=.  The base must be writable by the launching user;
=tmpfs= and =ramfs= bases are rejected because they would keep large temporary
files in memory.  For example, add
=#:desktop-temporary-directory "/home/user/.cache/app-tmp"= to the package's
=arguments= after creating that directory on disk.
=#:desktop-audio? #t= enables a private PulseAudio server with a playback
tunnel to the host's local PulseAudio-compatible socket.  This option requires
=#:desktop-application=.  The host socket is selected by a =unix:/...=
=PULSE_SERVER=, or =XDG_RUNTIME_DIR/pulse/native= when that variable is unset.
If no default socket exists, the application starts without audio.
=#:desktop-network? #t= enables LAN and Internet connections through
=slirp4netns= in a separate network namespace.  It requires
=#:desktop-application= and cannot be combined with =#:network? #t=, which
shares the host network namespace.  Private networking requires unprivileged
user namespaces and =/dev/net/tun=.  If its bridge cannot start, the launcher
exits before starting the payload.
The bridge uses a root mapping inside its user namespace for sandbox setup;
the application runs in a nested user namespace with the caller's UID and GID.
The host's =/etc/resolv.conf= must resolve under =/etc= or =/run= for
[[https://github.com/rootless-containers/slirp4netns/blob/master/slirp4netns.1.md][slirp4netns's filesystem sandbox]].

=#:set-environment= values can be strings or Guix file-like objects such as
=(file-append fontconfig "/etc/fonts/fonts.conf")=.  File-like values pin the
referenced store item and become absolute paths in the launched environment.

=#:share= binds a host path read-write; =#:expose= binds it read-only.  A path
can be an absolute string for the same path inside the container, a
=SOURCE . TARGET= pair, or =(environment "NAME")= for a path read from the
environment at launch.  An unset environment variable omits that mount.
Use existing host paths in place of the example paths.  Network access is
disabled unless =#:network?= or =#:desktop-network?= is true; the current directory is hidden by
default (=#:no-cwd? #t=).

If the payload provides =share/applications/*.desktop=, the wrapper exports
desktop files and icons from its own output.  Desktop =Exec= and =TryExec=
entries invoke the container launcher, including desktop actions.  The desktop
environment must include the installed Guix profile's =share= directory in
=XDG_DATA_DIRS= to discover them.

* AppImage build system
=roquix= includes =appimage-build-system= for repackaging Type 2 AppImages as
Guix packages.

** Desktop container packages
=feishin-container= and =logseq-container=
start the corresponding AppImage packages inside a Guix container.  Install
one variant per application; each provides the original command name and
its desktop entry:

#+BEGIN_SRC sh
guix install -L channel feishin-container logseq-container
feishin
logseq
#+END_SRC

Each application has a dedicated persistent home under
=${XDG_STATE_HOME:-$HOME/.local/state}/roquix/containers/<application>=,
created with mode =0700=.  That directory is mounted as HOME inside the
container.  Host HOME, the current working directory, and host XDG config,
data, and cache directories are hidden.

Each launch has a separate disk-backed =/tmp=, including simultaneous launches
of the same application.  This keeps Electron's temporary files and its
=--disable-dev-shm-usage= fallback off tmpfs.  The launcher removes this
directory on normal exit, startup failure, and handled interruption.  A killed
launcher can leave live application descendants, so directories left during
the current OS boot are retained.  The next launch using the same base reclaims
directories from previous boots, when those processes can no longer exist.
The host's =/tmp= contents and other launches' temporary directories are hidden.

A Wayland session is required.  A dedicated Weston compositor connects to the
socket selected by =WAYLAND_DISPLAY= and displays the application in its own
window.  The payload receives only that private compositor's socket and a
private runtime directory.  The compositor uses software rendering and runs
without host configuration, a desktop launcher, or a host clipboard bridge.
The launcher never
falls back to host X11 or shares the host runtime directory, D-Bus session,
Secret Service, SSH agent, host audio socket, GPU, or sound devices.  Each
container starts its own D-Bus session.  Standard input, output, and error
remain available; other inherited file descriptors are sealed before exec.

LAN and Internet connections are enabled with =#:desktop-network? #t=.
=slirp4netns= provides outbound networking and DNS in a private network
namespace, without a fixed list of servers or ports.  The bridge disables
access to the host loopback interface and provides no port forwards.  Host
abstract Unix sockets are outside the application's network namespace.
Services exposed on the host's LAN or public address remain reachable, as do
other LAN services.  These services must enforce their own authentication.
Network access also allows the application to transmit data from its private
home and explicitly shared directories.

Audio playback uses a private PulseAudio server whose only output is a
playback tunnel to the host's default sink.  The payload can record its own
playback monitor, but cannot enumerate the host microphone or other clients'
audio.  Loading additional modules is disabled.  The host can use PulseAudio
or PipeWire's PulseAudio compatibility server.  The launcher's runtime inputs
provide the PulseAudio client library.  Tray integration remains disabled.
Logseq can keep graphs in its private home.  To grant access to an existing graph, derive a package with
an explicit =#:share= mapping for that graph directory, for example:

#+BEGIN_SRC scheme
(arguments
 (substitute-keyword-arguments (package-arguments logseq-container)
   ((#:share _ '()) '(("/home/user/graphs/work" . "/graphs/work")))))
#+END_SRC

Display, keyboard, and pointer interaction pass through the private compositor.
Its protocols operate within the application's own desktop; the payload has
no direct connection to the host compositor or access to other applications'
windows and clipboard.  Weston is part of the trusted host-side boundary.
The container shares the host kernel and Guix's basic runtime devices and
pseudo-filesystems.  File, process, and network namespaces provide isolation
from the host; a separate kernel or a syscall filter is not provided.

AppImage package modules use =appimage-container-package= from
=(roquix packages appimage-container)= to define these variants.  The payload
keeps its ELF fixups and runtime tool wrappers.  The runtime profile includes
sandbox commands, a private D-Bus session, Fontconfig, DejaVu fonts, and
Japanese IPA fonts, along with PulseAudio playback support.

** Design
- Only Type 2 AppImages are supported.
- The extracted AppDir is installed privately under =lib/<name>/=.
- The generated wrapper exports =APPDIR= and executes =AppRun=.
- The exported =.desktop= file points to an icon inside the private AppDir.
- The build system does not globally install icon assets, which avoids
  collisions under =share/icons= or =share/pixmaps=.

** =#:patchelf-plan=
Use =#:patchelf-plan= for normal ELF fixups.

- Rewrites the ELF interpreter.
- Adds Guix library directories to =RUNPATH=.
- Best for shared libraries referenced through normal ELF dependency
  resolution.
- This is the preferred mechanism when it is sufficient.

** =#:ld-library-path-inputs=
Use =#:ld-library-path-inputs= only as an opt-in wrapper fixup.

- It appends selected input directories to =LD_LIBRARY_PATH= in the generated
  launcher.
- Entries use the same shape as the runpath entries in =#:patchelf-plan=:
  ~"mesa"~ means =<input>/lib=, and ~("nss" "/lib/nss")~ means a custom
  subdirectory.
- This is intended for cases where upstream loads libraries later by name,
  outside normal ELF dependency resolution, for example via =dlopen= or a
  library-specific module loader.

** When to use which
- Prefer =#:patchelf-plan= first.
- Use =#:ld-library-path-inputs= only when the application still fails to find
  a runtime-loaded module after =RUNPATH= has been fixed.
- Do not enable =LD_LIBRARY_PATH= globally in the build system by default,
  because it overrides the normal dynamic linker search order and can defeat
  the intent of =RUNPATH= fixups.

** Example
An AppImage package may need =#:ld-library-path-inputs= for modules that are
loaded later by name rather than through normal ELF =NEEDED= resolution, such
as NSS modules under =lib/nss=.
