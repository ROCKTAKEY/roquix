* Roquix: Guix channel for me
Note that this channel depends on [[https://gitlab.com/nonguix/nonguix][nonguix]],
and it might include non-free software.

* How to Use?
Write to =.config/guix/channels.scm=:
#+BEGIN_SRC scheme -n
  (cons* (channel
          (name 'roquix)
          (url "https://github.com/ROCKTAKEY/roquix"))
         %default-channels)
         #+END_SRC

Run =guix pull= and use the resulting =guix=.  Roquix's channel metadata makes
the extension discoverable as =guix extra-profile=; a channel installation
does not require =GUIX_EXTENSIONS_PATH= or =GUILE_LOAD_PATH=.

* Named extra profiles
=guix extra-profile= manages named profiles from declarative manifests and
combines already-built profile generations with =guix shell=.  It deliberately
does not re-evaluate a definition manifest while starting a shell.

** Definitions and generated profiles
A definition named =codex= is stored at:

#+BEGIN_EXAMPLE
$XDG_CONFIG_HOME/guix/extra-profiles/codex/manifest.scm
#+END_EXAMPLE

When =XDG_CONFIG_HOME= is unset, the path is
=~/.config/guix/extra-profiles/codex/manifest.scm=.  Its generated profile is:

#+BEGIN_EXAMPLE
~/.guix-extra-profiles/codex/codex
#+END_EXAMPLE

Names must match =[A-Za-z0-9][A-Za-z0-9._+-]*=.  Create or update the profile
explicitly:

#+BEGIN_SRC sh
guix extra-profile reconfigure codex
#+END_SRC

=reconfigure= accepts multiple names, =--all=, =--dry-run=, and the standard
Guix build options.  =--all= selects definitions only; a migrated generated
profile without a definition is not reconfigured.

** Shell composition
Start an interactive shell containing only the current =codex= generation:

#+BEGIN_SRC sh
guix extra-profile shell codex
#+END_SRC

The first =--= separates extra-profile names from arguments passed verbatim to
=guix shell=.  Project manifests must be explicit because the internally added
manifest disables =guix shell='s manifest auto-detection:

#+BEGIN_SRC sh
guix extra-profile shell codex -- \
  -CWNF \
  -m ./manifest.scm
#+END_SRC

Place optional =shell.scm= beside a profile's =manifest.scm= to configure
its shell.  The file is evaluated as Guile code, and its final expression must
return a =shell-configuration=.  Boolean fields default to =#f= and list fields
default to empty lists:

#+BEGIN_SRC scheme
(use-modules (roquix extra-profiles shell-configuration))

(let ((home (getenv "HOME")))
  (shell-configuration
   (container? #t)
   (network? #t)
   (pure? #t)
   (preserve '("^TERM$" "^DISPLAY$"))
   (environment-variables '(("EDITOR" . "emacs")))
   (extra-options '("--check"))
   (mounts
    (list
     (share (string-append home "/work")
            #:target "/workspace")
     (share (string-append home "/.cache/codex")
            #:target "/cache/codex"
            #:on-missing 'create-directory)
     (expose (string-append home "/.config/codex")
             #:target "/config/codex"
             #:on-missing 'skip)))))
#+END_SRC

The basic fields are =container?=, =network?=, =nesting?=, =link-profile?=,
=writable-root?=, =emulate-fhs?=, and =pure?=.  They accept =#t= or =#f=.
All except =container?= and =pure?= require an enabled =container?=.
=preserve= contains regular expressions naming environment variables to inherit;
they must be valid Guix regexps without an equals sign.  =environment-variables=
is an association list of string pairs =(name . value)=; values may contain
spaces and equals signs.  Names must be nonempty and cannot contain an equals
sign.  All option and environment strings must be NUL-free.

The expression runs when =extra-profile shell= starts, before Guix creates the
container.  Each =extra-options= string remains one command-line argument,
including spaces.  Specify mounts using =mounts=; =extra-options= cannot contain =--share=,
=--expose=, or the command boundary =--=.

=share= mounts a host path read-write; =expose= mounts it read-only.  Both accept
a host source path, optional =#:target=, and optional =#:on-missing=.  Source and
target paths must be absolute.  The target defaults to the source and is
normalized so that trailing slashes and =.= or =..= components do not hide
target conflicts.  Sources retain their spelling to preserve symbolic-link
resolution; they cannot contain an equals sign because Guix uses it to separate
source from target.  Directories, files, and sockets can be mounted.

The missing-source policy defaults to ='error=, which stops shell startup and
reports the profile name and source path.  ='skip= omits an absent source.
='create-directory= creates the source and missing parents with mode =0700=;
existing directory permissions are preserved, and an existing non-directory is
an error.  Creation is available for both =share= and =expose=, and occurs on
the host.  Permission errors, broken symbolic links, and non-directory parents
are errors even with ='skip=.  Missing target mount points inside the container
are created by Guix.

For multiple profiles, a boolean setting is enabled when any selected profile
enables it; =#f= contributes no request.  Environment inheritance patterns,
variable assignments, additional options, and mounts are collected in profile
order.  Later assignments to the same environment variable take precedence.
Basic flags are emitted once, followed by inheritance patterns, assignments,
additional options, and prepared mount arguments.  Container requirements and
mount conflicts are checked before directories are created.  Identical requests
for the same target are combined.  Different sources, access modes, or missing-source policies for
the same target are errors.  Parent mounts precede their children; independent
requests retain their order except where a parent must be moved before a child.

Mount requests require =(container? #t)= in at least one selected profile.
Additional options and explicit Guix arguments are passed through without
being interpreted as configuration fields, so supplying =-C= there does not
satisfy this requirement.  Saved settings and prepared mount arguments precede explicit arguments after the first =--=.  Keep the
command and its arguments after a second =--=.  Explicit Guix arguments are
passed through; the structured mount policies and conflict checks apply to
saved =mounts= settings.  Guix can still fail at execution if a source changes
after it has been checked.

Changes to =shell.scm= take effect on the next invocation without reconfiguring
the profile.  A name can have =shell.scm= without =manifest.scm= or a built
profile.  It appears in =extra-profile list=, has status =shell-only= in
=extra-profile show=, and starts a =guix shell= with an empty manifest.
=reconfigure --all= selects only names with =manifest.scm=.

Use a second =--= before a command executed inside the environment:

#+BEGIN_SRC sh
guix extra-profile shell codex -- \
  -CWNF \
  -m ./manifest.scm \
  -- codex
#+END_SRC

Multiple extra profiles are accepted.  Earlier names win file collisions;
an explicitly supplied project manifest wins collisions with extra profiles:

#+BEGIN_SRC sh
guix extra-profile shell codex texlive -- \
  -m ./manifest.scm \
  -- sh -c 'command -v codex'
#+END_SRC

=-p= and =--profile= are intentionally passed to =guix shell=, which rejects
their combination with the internally supplied manifest using its standard
diagnostic.  Options after the second =--= are command arguments and remain
unchanged.

At launch, each profile symlink is resolved through its current generation to
an immutable store directory.  The combined manifest is cached under
=$XDG_CACHE_HOME/guix/extra-profile/shell-manifests=, or under
=~/.cache/guix/extra-profile/shell-manifests= when =XDG_CACHE_HOME= is unset.
The cache directory has mode =0700= and manifest files have mode =0600=.

** Inspection and generation commands
#+BEGIN_SRC sh
guix extra-profile list
guix extra-profile show codex
guix extra-profile path codex
guix extra-profile generations codex
guix extra-profile generations codex 2d
guix extra-profile roll-back codex
#+END_SRC

=list= and =show= inspect filesystem state only.  They do not evaluate
definition manifests or start builds.  =roll-back= changes the mutable profile
symlink; the next shell launch consequently receives a different cache key.

** Guix Home
Guix Home can own definition files and XDG locations without performing an
implicit update.  For example:

#+BEGIN_SRC scheme
(use-modules (gnu services)
             (gnu home services)
             (gnu home services xdg)
             (guix gexp))

(services
 (list
  (simple-service
   'extra-profile-xdg-directories
   home-xdg-base-directories-service-type
   (home-xdg-base-directories-configuration
    (config-home "$HOME/.config")
    (cache-home "$HOME/.cache")))
  (simple-service
   'extra-profile-definitions
   home-files-service-type
   `((".config/guix/extra-profiles/codex/manifest.scm"
      ,(local-file "./codex-manifest.scm"))
     (".config/guix/extra-profiles/codex/shell.scm"
      ,(local-file "./codex-shell.scm"))))))
#+END_SRC

The XDG service exports the base-directory environment variables honored by
=guix extra-profile=.  Do not attach =guix extra-profile reconfigure --all= to
Home activation: a =guix home reconfigure= changes definitions, while the
separate extra-profile command intentionally decides when packages advance.

** Migration
An existing profile already located at
=~/.guix-extra-profiles/NAME/NAME= is immediately usable by =shell= even when
its definition is absent.  This supports temporarily unavailable definition
repositories and preserves the package derivations recorded in the current
generation.

To make a profile declarative, add its definition at the conventional path and
run =guix extra-profile reconfigure NAME=.  Profiles stored elsewhere should
be recreated at the conventional path from a manifest; avoid replacing them
with a link to another mutable profile because generation listing and rollback
are defined relative to the conventional profile basename.

** Developing and testing
Run the isolated unit and integration suite against the working tree with:

#+BEGIN_SRC sh
tests/extra-profile/run-tests.sh
#+END_SRC

The CLI tests use temporary Guix profiles that discover the checkout as a
channel.  This selects the working-tree modules even when roquix is installed:
Guix's channel module paths precede =GUILE_LOAD_PATH=.  The channel integration
test also runs without module-path or extension-path environment overrides.
Temporary HOME, XDG directories, and generated profile paths keep test state
separate from the user's Guix profile and extra profiles.

* Container launcher build system
=container-launcher-build-system= installs a wrapper in =bin/= that starts its
payload inside =guix shell -C=.  =#:payload= is a Guix package providing
=bin/<executable>=; the wrapper package has no source of its own.  Its
=inputs= are added to the container profile alongside the payload.

** Try and install the example
From this checkout, run the executable [[file:examples/hello-container.scm][GNU Hello example]] without installing it:

#+BEGIN_SRC sh
guix shell -L channel -f examples/hello-container.scm -- hello
#+END_SRC

Install the wrapper into the default Guix profile for ordinary =hello=
invocations:

#+BEGIN_SRC sh
guix package -L channel -f examples/hello-container.scm
hello
#+END_SRC

For an application defined as a named channel package, install it with
=guix install PACKAGE= after =guix pull=.  The installed executable starts the
container itself; callers do not need to supply =-C=.

** Runtime access
The wrapper uses a pure container and can preserve selected host environment
variables.  Add options to the package's =arguments= as needed:

#+BEGIN_SRC scheme
(arguments
 (list #:payload application-package
       #:executable "application"
       #:preserve-environment '("DISPLAY" "WAYLAND_DISPLAY" "XDG_RUNTIME_DIR")
       #:set-environment '(("APP_MODE" . "compact"))
       #:share '((environment "XDG_RUNTIME_DIR")
                 ("/home/user/work" . "/work"))
       #:expose '(("/home/user/assets" . "/assets"))
       #:network? #t))
#+END_SRC

=#:share= binds a host path read-write; =#:expose= binds it read-only.  A path
can be an absolute string for the same path inside the container, a
=SOURCE . TARGET= pair, or =(environment "NAME")= for a path read from the
environment at launch.  An unset environment variable omits that mount.
Use existing host paths in place of the example paths.  Network access is
disabled unless =#:network?= is true; the current directory is hidden by
default (=#:no-cwd? #t=).

If the payload provides =share/applications/*.desktop=, the wrapper exports
desktop files and icons from its own output.  Desktop =Exec= and =TryExec=
entries invoke the container launcher, including desktop actions.  The desktop
environment must include the installed Guix profile's =share= directory in
=XDG_DATA_DIRS= to discover them.

* AppImage build system
=roquix= includes =appimage-build-system= for repackaging Type 2 AppImages as
Guix packages.

** Design
- Only Type 2 AppImages are supported.
- The extracted AppDir is installed privately under =lib/<name>/=.
- The generated wrapper exports =APPDIR= and executes =AppRun=.
- The exported =.desktop= file points to an icon inside the private AppDir.
- The build system does not globally install icon assets, which avoids
  collisions under =share/icons= or =share/pixmaps=.

** =#:patchelf-plan=
Use =#:patchelf-plan= for normal ELF fixups.

- Rewrites the ELF interpreter.
- Adds Guix library directories to =RUNPATH=.
- Best for shared libraries referenced through normal ELF dependency
  resolution.
- This is the preferred mechanism when it is sufficient.

** =#:ld-library-path-inputs=
Use =#:ld-library-path-inputs= only as an opt-in wrapper fixup.

- It appends selected input directories to =LD_LIBRARY_PATH= in the generated
  launcher.
- Entries use the same shape as the runpath entries in =#:patchelf-plan=:
  ~"mesa"~ means =<input>/lib=, and ~("nss" "/lib/nss")~ means a custom
  subdirectory.
- This is intended for cases where upstream loads libraries later by name,
  outside normal ELF dependency resolution, for example via =dlopen= or a
  library-specific module loader.

** When to use which
- Prefer =#:patchelf-plan= first.
- Use =#:ld-library-path-inputs= only when the application still fails to find
  a runtime-loaded module after =RUNPATH= has been fixed.
- Do not enable =LD_LIBRARY_PATH= globally in the build system by default,
  because it overrides the normal dynamic linker search order and can defeat
  the intent of =RUNPATH= fixups.

** Example
An AppImage package may need =#:ld-library-path-inputs= for modules that are
loaded later by name rather than through normal ELF =NEEDED= resolution, such
as NSS modules under =lib/nss=.
